# CLAUDE.md: Universal Development Principles

> Base file for every project in this folder. Project files extend it and win on conflict (they're the local source of truth).
>
> **This file is loaded into every session, so everything in it is paid on every cold start.** Keep it to rules that fire on most sessions. Detail lives in the companion files below — load one when its trigger fires, not by default.

## North star: ship small things that work end-to-end

One rule drives the rest: **build the smallest version that works, then add only what the next real user need demands.** (Karpathy: "make it work, then make it good." levels.io: "ship it ugly, ship it now.") A working ugly thing teaches more in a day than a plan teaches in a month.

- **No half-finished work.** A feature ships end-to-end or stays a branch, never merged 80% done with a TODO.
- **No speculative abstraction.** Three similar lines beat a premature helper. Build the helper the second time you need it.
- **No future-proofing without a present user.** Every config knob, plugin point, and flag is dead weight until someone uses it.

## Agent Workflow: Explore → Plan → Code → Verify

Never blindly write code.

1. **Explore.** Find relevant files and understand existing patterns before touching anything.
2. **Plan.** Assess blast radius. For significant changes, present 2–3 approaches with pros/cons and get approval before coding.
3. **Code.** Implement following the rules below.
4. **Verify.** Run tests, use the feature, fix all failures before declaring done.

**Read before edit**, always, even if you read the file earlier this session. **Ask for options first** on non-trivial tasks; the first plausible plan is rarely the best. **Close the loop yourself**: build so the agent can compile, lint, test, and verify its own output. (Karpathy: "agentic coding works when the eval is the loop.")

**A spec's data assumptions are guesses until you query the data — including a spec you wrote.** A design doc authored from a codebase audit encodes plausible-sounding distributions, and implementing them faithfully ships confident advice built on numbers nobody measured. Three assumptions in one spec section died to a single query each: a "$1–8 market" was really $1–**$28** (quoting $8 as the ceiling would lose exactly the contested cases the feature existed for); a proposed `<10 / 10–20 / 20+` value tier was **empty by construction** in its first tier; and a proposed split turned out to be a split on a variable that *doesn't vary* in the relevant population. **Before implementing any rule keyed off a range, tier, threshold, or correlation, run the one-line query that checks it.** Then record what the data said next to what the spec said — the next reader needs to know which one won. This applies to a plain **count** just as much: a workstream scoped as "sweep the 20 offenders" turned out to describe **108**, a 5× miss that changed the size, the risk, and the reporting of the task. The delta is often the most useful thing you'll report. (Full cases in [LEDGER.md](LEDGER.md); related rules in [DATA.md](DATA.md).)

**A checker that does not model the real object measures nothing, and it will tell you so in the most convincing possible way: as a finding.** Twice in one session, on the same underlying mistake. A corpus validator merged enrichment data over the primary records with the wrong precedence — the browser's join is fill-if-empty, the validator's was overwrite — so one layer's coordinates replaced another's, and a geometric invariant duly reported **2,146 violations that did not exist**. Later, a link checker sampled bare records instead of the enriched ones the UI renders, and **"passed 40/40" while exercising exactly one of fourteen fields**. Both looked like healthy tooling: one produced alarming output, the other reassuring output, and neither was measuring the thing. Before believing a checker, make it reproduce a known-good case and a known-bad one — and if the system under test has a join, a merge, or a precedence rule, the checker must implement *that* rule, not a reasonable-looking one. Corollary: **a validator must mirror the code it verifies, not an improved version of it.** "Improving" a re-derivation to fall back to a more authoritative field produced 38 instant false mismatches, because it started measuring a policy nobody had implemented; if the fallback is right, change the code first and let the check follow.

**If you obtained approval by characterizing a set, and reading the set shows the characterization was wrong, re-open it — don't execute the letter of the approval.** Approval granted on a summary covers the summary, not whatever the set actually contains. Having described 75 records as "clear noise" on the strength of a keyword pass, reading them showed 4 were load-bearing (an export-control action naming 32 entities in the very country the project exists to track). Executing "drop all 75" would have been faithful to the words and destructive in fact. Narrowing a destructive action below what was authorized, and saying so plainly, is always safe; widening or blindly completing it is not. Corollary: **a keyword filter is triage, not a verdict** — it has false positives and false negatives, so read the titles before deleting anything.


- **`new URL(...).pathname` is percent-encoded; use `fileURLToPath` for anything that touches the filesystem.** A test spawning a script via `execFile(process.execPath, [new URL("../scripts/x.mjs", import.meta.url).pathname])` failed in a checkout living under a directory with a space in its name, because `.pathname` handed back `%20` and node could not resolve the file. The failure surfaces as the child exiting with the wrong code, which reads like a bug in the script under test rather than in the path. `fileURLToPath()` returns the real path.

- **Never fan out a fleet of parallel finder agents for a review that fits one context.** A 10-agent /code-review fan-out re-sends the diff and repo context ten times (~1M+ tokens), and on 2026-08-09 it also tripped the session usage cap — all ten died before returning a single finding, while the same review done inline afterwards found 4 real issues for a fraction of the cost. Run review angles sequentially in the main context for diffs up to ~1–2k lines; reserve subagents for work that genuinely exceeds one context, and then use one or two, not a swarm. (2026-08-09)

## Session & token economics

The 5-hour usage limit is **one shared pool** across the main loop, every concurrent session, and every subagent. Context is charged per turn, not per session.

- **Resuming a rate-limited session is the single most expensive action available — unless the reset lands inside the cache TTL.** Prompt-cache TTL is ~1 hour, so after a longer block every cache is dead and the first request re-writes the *entire* context at the 2× 1h-write rate. Measured across 45 limit hits (2026-08-08, 14-day audit): resumes **<1h after the hit re-paid a median of 2K tokens** (cache alive — nearly free); resumes **>1h after re-paid a median of 150K each, 8M total** across 32 sessions. The error message contains the decision input: `resets 12:10am`. **Reset < ~1h away → park and resume right at reset. Reset hours away → resume only the one session holding irreplaceable state; start the rest fresh.** (Original 2026-08-04 case: eight sessions resumed after a ~3.5 h block burned ~1.5M tokens on cache re-writes before a single useful word.)
- **An error'd session more than ~1h old has the same resume economics as a rate-limited one.** A network drop auto-retried in the moment is nearly free (cache still alive; measured re-pay ≈0). The expensive habit is leaving a big-context session dead on a network/auth error and coming back hours later: such resumes re-paid **62–402K each** (a full context re-write at 2×). Same rule as above: after >1h, fresh session unless its state is irreplaceable.
- **Concurrent sessions multiply the fixed cost against one pool — and a wide fleet guarantees the wall lands mid-flight.** Eight live sessions in 21 minutes read **27.2M tokens of context to produce 88.9K tokens of output** — 305:1. Over a full 2-week window, 56 of 94 active hours had 2+ sessions live; on limit-hit days **17–18 sessions were live in single hours**, so the 5-hour wall stranded everything at once and each resumed session paid the >1h re-write tax above. Serialize; never launch a fleet late in a window; two worktrees of the same project open at once is the common self-inflicted case. Repeated window slams also compound upward into the **weekly** limit, which no window timing fixes.
- **Context size is a per-turn tax, and past a point it also costs correctness.** A 724K-token session pays ~72K effective tokens *every turn* just to exist. The 14-day audit (2026-08-08): **72 of 163 sessions crossed 200K context and carried 91% of all spend**; the 13 that crossed 600K carried 54%; peaks reached 926K. The quality half is **context rot**: across 18 models including Claude 4, reliability degrades *non-uniformly* as input grows — models hit cliffs (fine at 32K, collapsing at 64K) rather than declining smoothly, and they score **worse on logically coherent documents than on shuffled ones** ([Chroma](https://www.trychroma.com/research/context-rot)). So consolidating everything into one enormous session is not the fix for concurrency cost; it trades a billing problem for a reasoning problem. Commit, `/clear`, and reopen once a session passes ~200K — a fresh session on the same task is cheaper *and* sharper.
- **Measure before blaming; the session you're in is rarely the one burning.** Method: read `~/.claude/projects/**/*.jsonl`, **dedupe by `requestId`** (each request is logged 2–3×, so raw line counts overstate by ~2.2×), then weight cache writes **by TTL bucket** — `usage.cache_creation.ephemeral_5m_input_tokens` ×1.25, `ephemeral_1h_input_tokens` ×2.0 (writes have moved to the 1h bucket: 86% of write tokens in the 14-day audit, so a flat ×1.25 understates ~10%) — plus `cache_read_input_tokens` ×0.1 and `output_tokens` ×5. Transcripts log usage only for *successful* requests, so retry costs measured this way are floors. The session accused of causing a 20%→40% jump was 4.4% of that hour.
- **Fan-out is not the usual culprit — check before optimizing it.** Subagents were 8.1% of spend in the first measured window and 9.1% at 2-week scale (2026-08-08); concurrency and context size were the other ~91%. Fix the expensive thing, not the conspicuous one. Adversarial code review measured the same way was ~2% of a window per agent and paid for itself (tiers and the conditions that make it worth it: [AGENTS.md](AGENTS.md)).
- **The main-loop model is the biggest budget lever after context size; per-subagent model choice barely moves the bill.** 14-day split: **Opus-tier 53% of weighted spend, Sonnet 31%, Haiku 0.3%** — while subagents in total were 9%. When the 5-hour budget is chronically tight, run bulk autonomous/mechanical sessions on Sonnet and spend Opus/Fable on design and judgment turns; picking Haiku for subagents while the main loop runs Opus optimizes the 9% and ignores the 91%.
- **Any short turn taken late in a big session is expensive, and committing is the common case.** 20 commit turns averaged **517K weighted tokens with 3.8% of it as output** — the rest was re-reading and re-caching the conversation. Cost is `round-trips × context size`: one `"commit everything so far"` took 44 round trips in a 700K session for 3.0M tokens, versus 43K for a tight one. Batch the shell calls and commit early ([GIT.md](GIT.md)). The same arithmetic governs autonomous runs: measured sessions ran **100–287 round trips per human prompt**, so a "go do it" prompt at 600K context costs 6–17M weighted — **launch long autonomous work in a fresh small session, not as the last turn of a big one** (~8× cheaper for the same work).
- **Before re-doing expensive work in a fresh isolated environment (worktree, container), check whether the primary/canonical environment already has it.** A gitignored checkpoint directory looked missing in a fresh git worktree — but the job that produced it had run against the main checkout, not a worktree, so the files were still there untouched. One `git worktree list` plus a look in the listed paths' equivalent directories can turn an assumed full re-run into a free recovery.

## Communication style

- **Concise.** No filler, apologies, moralizing, or generic advice.
- **Show your work** only when it changes the answer.
- **Fail loud.** No catch-all handlers that swallow errors. Raise or log.
- **State results, not effort.** "Tests pass," not "I worked hard to get tests to pass."
- **When a message carries several distinct requests, enumerate them into a checklist and confirm each before declaring done.** A subset silently dropped reads as "you missed my comments" (it happened: a batch of ~6 review notes got ~4 done, and a general "also add X, it can fit anywhere" instruction was skipped on the non-active files). Restate the list back and tick it off. A scope word — "every site," "all," "the rest" — means the full set, not the active subset: one pass removed a deck section from 4 of 10 decks when the ask was all 10. Re-read the last few user messages before saying "done."
- **The AI-writing tells apply to your own responses, not just shipped copy.** Antithesis, corrective negation, parataxis, rule of three, hedging qualifiers, performed enthusiasm: same banned list either way. Full inventory in [DESIGN.md § 11.1](DESIGN.md).

## Architecture principles

- **No over-engineering.** Only changes directly requested or clearly necessary.
- **Boring tech wins.** Vanilla JS, SQLite, static HTML, system fonts, plain Python beat the framework-of-the-month. Every dependency is a future bug, migration, and advisory. (levels.io: "boring tech is the secret.")
- **Single source of truth.** Constants, configs, shared types derive from one place. If a value is duplicated, test that the copies match. **A hand-written list that mirrors a registry rots silently, and it rots worst inside the code meant to catch drift.** One session hit this three times — a test fixture listing payloads to copy, a preview builder listing data files to embed, a test asserting an "exactly eight signatories" roster — and all three *passed while wrong*. The tell is a literal sitting next to the thing it claims to enumerate: `for name in ("a","b","c")` beside a `REGISTRY` dict, or an `EXPECTED = {...}` beside the file that defines the truth. Derive it — `for name in refresh.PAYLOAD_FILES`, `sorted(DATA_DIR.glob("*.json"))`, `assert flagged == set(load_registry())` — and the check becomes incapable of going stale. **A parity test over a key→value mapping (e.g. a status → CSS-class dict) that only checks the mapping's KEYS against an enum will pass while a VALUE is wrong** — a `RATE_CASE_BADGE_CLASS` mapped `approved` to `badge-tariff-approved` while the stylesheet only ever defined `badge-tariff-status-approved`; every badge rendered uncolored, and `assert set(js_keys) == set(STATUSES)` stayed green throughout, because a mismatched value is invisible to a keys-only check. When the mirror is a mapping, assert the mapped *value* resolves to something real (`assert f".{class_name}" in css`), not just that the key set matches.
- **Modular layers.** Data fetching, processing, storage, presentation: distinct modules.
- **Idempotent operations.** Re-running is safe (`INSERT OR IGNORE`, cache checks, dedup by key), but that protects re-runs, not concurrent writers. Never run two instances of the same stage on overlapping inputs; both writing one output dir corrupt each other.
- **A resumable multi-step pipeline commits each side-effect's result as it lands, and gates re-execution on it.** Persist the external id (posted-tweet id, charge id) in its own commit *before* the terminal state transition — setting `id` and `status=done` together loses the id on a rollback if the commit fails after the side-effect fired, and the retry re-fires it (double-post, double-charge). An idempotency key on the external call closes the last of the gap. Regression-test that a retry with the id already set makes no external call.
- **Check-then-insert races need a DB-level constraint, not an app-level guard.** A partial unique index (catch the resulting `IntegrityError`) closes the race a check-then-write app check can't. Two writers to one DB file should collapse to one owner + a thin client, not two ORMs both writing.
- **A display/formatting helper duplicated across render paths (mobile vs. desktop, page A vs. page B) will diverge.** One gets a fix, the other doesn't. Extract one shared function; don't rely on remembering to touch every copy. Same holds for state machines and async workflows. On the second occurrence of identical logic, stop and extract before shipping.
- **Precompute derived values at ingest, not per call.** Compute a hot-loop value (e.g. a per-record search string) once at write time and store it. No per-call fallback that re-derives it — that silently defeats the optimization; prefer "no key → no match" so a missed index fails loud.
- **Static when possible.** Baked data over runtime backends. A `docs/` folder on GitHub Pages beats a server to babysit.
- **Cost-optimized.** Free tiers; cheapest resource that meets the requirement.
- **CLI-first.** Build CLI entry points before UI so agents can self-validate output.
- **Minimize page weight and request count.** Content sites stay lightweight: fewest requests, smallest payload.
- **Tree-shake and code-split.** Lazy-load what a page needs; don't bundle every controller everywhere.
- **Benchmark against best-in-class.** If the simplest site in the org is orders of magnitude lighter, review the build.
- **Document subsystems.** A `docs/` folder noting non-obvious subsystems, decisions, and correct CLI invocations. One line prevents repeated mistakes.
- **One generic `data-refresh` skill; per-project refresh playbooks.** Never write a per-project refresh *skill*. The global `data-refresh` skill (`~/.claude/skills/data-refresh`) supplies the procedure and universal rules; everything project-specific (entry points, gates, data layout, quirks) lives in `REFRESH.md` at that project's root, versioned with the code it describes. Every refresh run appends learned patterns to the playbook; structural pipeline changes get edited into its body. A project without a `REFRESH.md` gets one bootstrapped on its first refresh.
- **Verify an external service's real contract before building on it: format, pricing, ToS.** A plausible-sounding assumption can be flatly wrong and leave the code dead on arrival ("this print vendor accepts SVG" when it needs PNG, "this platform has a free API tier" when that tier is gone, "this free API is fine for a commercial app" when its ToS bars that use). One targeted doc/pricing/ToS check before committing to a pipeline shape saves a rebuild; when the loop is keyless anyway, a dry-run that fails loud on the missing piece beats a "working" path built on the wrong contract.
- **A lazy-loader's "fetch at most once" guard must cache the in-flight *promise*, not a boolean set after the fetch resolves.** `if (!state.xLoaded) { fetch... ; state.xLoaded = true }` looks idempotent but isn't under concurrency: two callers in the same `Promise.all` (or one caller calling another function that itself calls the loader) both read the flag as false before either `await` settles, so the payload fetches twice. Cache the promise instead: `let _xPromise = null; function loadX() { if (!_xPromise) _xPromise = (async () => {...})(); return _xPromise; }` — every caller gets the same in-flight (or resolved) promise. Regression-test it by asserting the network request fires exactly once.
- **A `Promise.all` mixing a view's primary payload with a secondary/decorative one needs the secondary's promise caught individually**, not the whole array — otherwise the secondary failing rejects the primary too and blanks a view that would otherwise have rendered fine. `Promise.all([primaryFetch(), secondaryFetch().catch(err => log(err))])`.
- **A doc comment stating an invariant doesn't enforce it.** A field comment said "the UI must not claim X without confirming Y," but the render code still used a bare fallback (`tier ?? 'covered'`) that ignored the sibling field Y entirely — 58 records silently violated a rule written down right next to the field. Grep every read site of a "default" value against the sibling field that's supposed to override it; don't trust that stating the rule enforces it.

## Git & PR workflow

- **Stacked-PR merge sequence:** merge the base PR first *without* deleting its branch (so the dependent PR's diff still resolves), then retarget the dependent PR's base to the trunk branch (`gh pr edit N --base main`) — it recomputes mergeability cleanly against the trunk's new HEAD as long as the base PR's branch still exists at retarget time. Only delete both branches after the dependent PR has also merged.
- **`gh api .../pulls/{n}/reviews` (or the equivalent GitHub REST call) rejects `event: "REQUEST_CHANGES"` / `"APPROVE"` when the authenticated user is the PR's own author** — 422 `"Review Can not request changes on your own pull request"`. Use `event: "COMMENT"` for a self-authored review submitted via the API.
- **`git merge-tree $(git merge-base A B) B A` surfaces real conflicts without attempting an actual merge** — use it to confirm a stale-looking branch genuinely conflicts with the trunk (not just "hasn't been touched in a while") before deciding to close it as superseded rather than merge it.
- **When several tools/scripts write the same data files, keep their serialization settings identical** (e.g. `json.dumps(..., ensure_ascii=False)`) — one script using the library default while its siblings pass an explicit option produces pure re-encoding churn on every alternating run, which reads as "someone keeps touching this file" when nothing about the content actually changed. Verify a normalization fix is semantically inert (`json.loads(before) == json.loads(after)`) before committing it.
- **Never merge a long-unmerged branch on the assumption its IDs are still free.** A branch that has sat for months carries issue and backlog IDs that the trunk has since reassigned to unrelated work — merging it yields two rows per ID describing different bugs, in exactly the files future sessions are told to trust. Triage first: re-derive the free ID range from the trunk file *at the moment you write*, not from a read taken earlier in the session, because a parallel session can claim an ID mid-triage.
- **Triage an old branch against the current code, not against its own descriptions.** Its commit message describes the world on the day it was written. Expect a mix: some findings still reproduce, some were silently fixed by unrelated work, some became documented-by-design. Only the current source says which is which — check each one before carrying it forward.
- **Consolidate conflicting dependency PRs; don't cherry-pick them.** Bot-authored bumps each rewrite the lockfile from the same base, so they conflict pairwise and the merge product is a hand-resolved lockfile nobody can review. Apply every version constraint to the manifest together and regenerate the lockfile in one install — same destination, reviewable path.
- **A bounded queue sitting exactly at its bound is a ceiling, not a coincidence.** Five open bot PRs against a limit of five means *at least* five, with the remainder suppressed and invisible. Raise or regroup before concluding you've seen the backlog.
- **A pinned dependency needs its version-locked siblings pinned too, or the pin leaks.** Pinning a framework while leaving its lockstep companion (a config, plugin, or types package that ships on the framework's own version line) unpinned lets an automated upgrade pair incompatible halves. A pin expressed on one package name is not a pin on the constraint you meant.
- **Rank dependency upgrades by measured effect, not by how alarming the version jump looks.** The scariest bump in a batch — two majors across every test file — can be the one carrying the only security fix, while a reassuring patch fixes nothing. Diff the audit before and after rather than reasoning from semver distance.

## Issue tracking (`issues.md`)

A living audit trail in the project root.

- Each bug: date, area, description, root cause (**code bug** vs. **test bug**), status (Open / Fixed).
- On resolution: the fix + the commit. Check whether a regression test is needed.
- **A quality gate that cannot run still reads as configured.** Inherit a repo, and `package.json` (or the Makefile, or CI config) will list scripts that have never once been executed — a lint script that exits into an interactive setup prompt because no config file exists, a test script pointed at a deleted directory. The declaration is not the gate. Run every declared script once, early, and record which ones are real.

## Backlog (`backlog.md`)

- Add ideas immediately. Don't lose them. Each: description + priority (low / medium / high).
- Reprioritize periodically; demote stale "high" items rather than let them rot.

## Python standards *(when the project uses Python)*

- Type hints on all functions. `pathlib.Path` for paths. `logging`, not `print`, for runtime output.
- All constants in one config module. Pydantic for validation. Python 3.9+ unless specified.
- Pin dependencies with `==` (hash-locking in [SECURITY.md](SECURITY.md)).
- **A model built via `**{k: v for k, v in existing.items() if k not in (...)}` plus explicit override kwargs must exclude every explicit kwarg from the spread, not just the ones being replaced.** Otherwise `TypeError: got multiple values for keyword argument '...'` fires the moment `existing` already carries that key — which can mean it only fails on a re-run against already-processed data, not on first run. Add every explicit override to the exclusion set the day you add it.
- **A module constant used as a default argument binds at import, so it can never be monkeypatched.** `def write(path: Path = QUEUE_PATH)` looks configurable and isn't. Take `path: Path | None = None` and resolve `path = path or QUEUE_PATH` inside, or a test that believes it redirected a write puts real rows in `data/`.

### 2026-08-11 session additions (nuclear financing layer)

- **The browser pane's console buffer survives `console.clear()` AND dev-server
  restarts.** A fixed hydration error kept appearing through a restart and
  three reads because the extension replays captured history; only a fresh tab
  (`tabs_create`) gave a clean buffer. Verify any console-error fix from a new
  tab, never the old one.
- **Chart figures in a PDF are unrecoverable from linearized text — position-parse
  them.** Extracted text interleaves a chart's numbers across series with no
  mapping; PyMuPDF `get_text("words")` with x/y coordinates resolves which
  value belongs to which series. Never quote a chart value read off linearized
  order.
- **Quote-lock spans must dodge PDF extraction glyph damage.** Text layers
  carry ligatures ("ﬁrst" is U+FB01), soft hyphens, and footnote digits glued
  to figures ("$1696" is $169 + footnote 6). Pick verbatim spans that end
  before the damaged region and normalize whitespace on both sides of the
  comparison.
- **Never anchor a structural doc insertion on a line prefix.** An Edit
  anchored on the first words of a list item split the line and duplicated two
  headings. Anchor on complete lines or heading boundaries, and verify heading
  counts (`grep -c "^## "`) after any structural edit to a doc.
- **Budget the review loop: fix the class after round two, do not let the bot
  enumerate it.** When a review round's findings are instances of an
  already-named class rather than a new class, stop re-requesting reviews,
  sweep the class exhaustively yourself, and merge. Six rounds on one PR
  proved rounds 3+ were enumeration the author should have done in one pass.
- **Never truncate a gate's output; print its exit code.** `lint | tail -1`
  reported green while eslint was failing; the error block was swallowed and
  a lint failure merged to main. Run the gate, echo `$?`, read the summary,
  never a one-line slice.
- **Calibrate a new CI gate against the codebase before landing it.** Run every
  check locally first and sort what it finds into fix-now / demote-to-warning /
  turn-off-with-a-stated-reason. A gate that is red on arrival teaches everyone
  to scroll past it, and the first real failure gets scrolled past for exactly
  the same reason. Adding CI to a site repo surfaced 162 html-validate errors
  that were almost entirely two disabled-by-design rules; the one genuine
  finding was worth more than the other 161.
- **A check whose input includes time or VCS metadata must treat that drift as
  advisory.** Anything derived from commit dates, `git log`, or "now" moves
  without anyone changing content, so failing on it is a guaranteed false
  positive on a slow enough PR. Classify and report it; fail only on the part
  that is actually content.
- **Prefer a checker you can run locally over one you can only run in CI.**
  Swapping a planned `lychee` job for a ~90-line stdlib link checker meant it
  could be proved green *and* negative-tested before committing, and it fit the
  repo's zero-dependency idiom for free. A gate you cannot execute while writing
  it is a gate you are guessing at.
- **`git filter-branch --msg-filter` — never pipe the message through
  `awk 'BEGIN{RS=""}'`.** It collapses every newline, so the whole commit body
  becomes the subject and `git log --oneline` turns into a wall of text. Use a
  `python3 -c` filter that splits and rejoins on newlines. The recovery is
  `refs/original/refs/heads/<branch>`, which filter-branch writes before
  rewriting — `git reset --hard` to it and redo.
- **An auth wall turns a measuring tool into a confident liar.** Point Lighthouse
  (or a crawler, or a visual-diff job) at a URL behind SSO and it follows the
  302 and measures the *login page*, reporting real-looking scores for a
  document you never wrote. A CI run reported perf 0.34 and LCP 9.2s for a site

### 2026-08-14 (client-side caching, cross-tool session reader, dashboard simplification)

- **A cache write placed inside a "did my component unmount?" guard silently exempts exactly the requests that needed caching most.** The guard exists to skip `setState` after unmount; putting the `cache.set` behind it too meant any request that outlived its component contributed nothing.
